## 0. 怎么用这份指南

### 三条规则

1. **自己敲代码**：每关的填空骨架只是提示，不要直接复制完整成品。
2. **先跑通，再重构**：先写能工作的“笨版本”，再消除重复。
3. **卡住先排查，再要提示**：连续卡住 20 分钟以上，再升级提示层级。

### 每关流程

```text
读目标 → 看知识点 → 自己写 → 在 Wokwi 运行 → 对照验收标准 → 下一关
```

遇到问题按下面顺序升级，不要一上来就要完整代码：

1. **概念**：这个元件/函数是干什么的；

3. **API**：给出函数名、参数、返回值；
4. **定位**：指出你代码的哪一行有问题；

## 1. 任务速览

| 项目 | 要求 |
|---|---|
| 平台 | Wokwi 在线仿真（wokwi.com） |
| 开发板 | Raspberry Pi Pico |
| 语言 | MicroPython |
| RGB 灯 | 共阴：COM 接 GND，颜色脚高电平点亮 |
| 引脚 | GP10、GP11、GP12 初始化为输出 |
| 限流电阻 | 每个颜色脚串一个 220Ω，不允许省 |
| 效果一 | 红、绿、蓝依次单独亮，各 1 秒 |
| 效果二 | 全亮（白光）1 秒、全灭 1 秒，交替闪烁 |
| 效果三 | 红+绿、绿+蓝、蓝+红，依次显示黄、青、紫，各 1 秒 |
| 代码约束 | 最大缩进两层；全亮/全灭统一操作，不许抄三遍赋值 |
| 验收 | 上电自动运行；效果循环；颜色顺序正确；改 `DELAY` 快慢变化 |

最终现象：板子上电后自动循环播放“单色 → 白光闪烁 → 黄青紫”，不需要按键，也不需要电脑干预。

## 2. 第 0 关：建工程、认元件、画接线

**目标**：在 Wokwi 新建 Pico + MicroPython 工程，摆好元件并完成共阴接线。

### 2.1 建工程

1. 打开 <https://wokwi.com/>，**先登录**（匿名工程可能丢失）。
2. New Project → 搜索 **Raspberry Pi Pico** → 选择 **MicroPython**。
3. 直接运行默认模板，确认仿真能启动；在 `main.py` 开头加一行 `print("hello")`，看控制台输出。
4. 给工程命名并保存，例如 `work1-rgb-led`。

### 2.2 认识两个文件

| 文件 | 作用 |
|---|---|
| `main.py` | 板子上运行的程序 |
| `diagram.json` | 电路描述：`parts` 是元件，`connections` 是连线 |

图上接的线，就是 `connections` 里的记录；程序里的引脚号，必须和它一致。

### 2.3 加元件

- 点蓝色 **`+`**，搜索 `rgb`，选 **RGB LED**（5mm 四脚）；
- 再加 3 个 **Resistor**。

元件类型和属性：

| 元件 | 类型 | 关键属性 |
|---|---|---|
| Pico | `wokwi-pi-pico` | — |
| RGB 灯 | `wokwi-rgb-led` | `"common": "cathode"` |
| 电阻 | `wokwi-resistor` | `"value": "220"` |

**最容易漏的一步**：`wokwi-rgb-led` 默认是**共阳**。任务要求共阴，必须把 `attrs` 改成：

```json
"attrs": { "common": "cathode" }
```

如果属性面板里找不到，就直接编辑 `diagram.json`。不改这一项，现象会全反或不亮。

### 2.4 接线

| RGB 灯引脚 | 连接 | Pico 引脚 | 建议线色 |
|---|---|---|---|
| COM（公共端） | 直接接 GND | `pico:GND.1` | 黑 |
| R（红） | 串 220Ω | `pico:GP10` | 红/橙 |
| G（绿） | 串 220Ω | `pico:GP11` | 绿 |
| B（蓝） | 串 220Ω | `pico:GP12` | 蓝 |

接线方法：**点一个引脚，再点另一个引脚**。电阻必须串在 RGB 灯和 GPIO 中间，不能灯直接连 GPIO。

### 2.5 验收

- [ ] `diagram.json` 里 RGB 灯有 `"common": "cathode"`；
- [ ] 三个颜色脚各有一个 220Ω 电阻；
- [ ] COM 接的是 GND，不是 3V3；
- [ ] R/G/B 分别接到 GP10/GP11/GP12；
- [ ] 走线不交叉打结，颜色脚没有分错。

仓库里的 [`diagram.json`](diagram.json) 就是一个已检查通过的参考接线，可以用来对照，但建议先自己画一遍。

## 3. 第 1 关：让一盏灯亮起来

**目标**：理解 `machine.Pin`、输出模式、高电平点亮、`time.sleep()`。

### 知识点

- `Pin(10, Pin.OUT)`：把 **GP10** 设成输出。`10` 是 GPIO 编号，不是物理第 10 脚。
- `.value(1)`：输出高电平，共阴灯对应颜色点亮；`.value(0)` 熄灭。
- `time.sleep(1)`：等待 1 秒。

### 填空骨架

把 `main.py` 全部替换成下面内容，自己补 `____`：

```python
from machine import Pin
import time

led = Pin(____, Pin.OUT)   # 先接 GP10

while True:
    led.value(____)        # 点亮
    time.sleep(____)       # 亮 1 秒
    led.value(____)        # 熄灭
    time.sleep(____)       # 灭 1 秒
```

参考运行结果：红色 LED 亮 1 秒、灭 1 秒，循环。

### 三色验证

**只改代码里的引脚号，不要动接线**：

1. `Pin(10)`：应该亮红色；
2. `Pin(11)`：应该亮绿色；
3. `Pin(12)`：应该亮蓝色；
4. 最后改回 `Pin(10)`。

把实测的“元件 R/G/B 脚 ↔ GP10/11/12”记录到 [`README.md`](README.md) 的“实测颜色映射”表里。

### 验收

- [ ] 红色能单独闪烁；
- [ ] 只改引脚号，绿色、蓝色也能分别亮；
- [ ] 能说出 `1` 和 `0` 分别代表高/低电平，以及为什么共阴灯高电平亮。

### 排错顺序

**电源 → COM/公共端 → 电阻 → 代码引脚号 → 颜色线是否插错**。九成错误是某根线没点上，或者引脚号写错。

## 4. 第 2 关：效果一“红、绿、蓝依次单独亮”

**目标**：把三个引脚组织成元组，写出“同一时刻只亮一个”的效果。

### 第一步：先写“笨版本”

先写三组重复代码，把红 → 绿 → 蓝依次亮跑通。每组大致是：

```text
点亮一个脚 → sleep 1 秒 → 全灭 → 换下一个脚
```

这一步不追求好看，先建立“我的接线和颜色映射是对的”这个基线。

### 第二步：感到重复的痛苦

问自己两个问题：

- 如果改成 30 个灯，要改几行？
- 如果延时从 1 秒改成 0.5 秒，要改几处？

### 第三步：重构

定义常量、元组和两个辅助函数。填空：

```python
from machine import Pin
import time

DELAY = ____
PINS = (Pin(____, Pin.OUT), Pin(____, Pin.OUT), Pin(____, Pin.OUT))
SINGLE = ((1, 0, 0), (0, 1, 0), (0, 0, 1))

def set_all(value):
    for pin in PINS:
        pin.value(____)

def show(color):
    for pin, value in zip(PINS, color):
        pin.value(____)
    time.sleep(____)
    set_all(____)

while True:
    for color in SINGLE:
        show(color)
```

要点：

- `SINGLE` 的三行分别代表红、绿、蓝；
- `show(color)` 负责“按颜色设置三个脚 → 等待 → 全灭”；
- `set_all` 是全亮/全灭的唯一入口，后面第 3 关直接复用；
- `PINS` 的顺序必须和接线一致。

### 验收

- [ ] 红 1 秒 → 绿 1 秒 → 蓝 1 秒，顺序正确；
- [ ] 切换时没有残留鬼影；
- [ ] 代码里不再有三行重复赋值；
- [ ] 能解释 `zip(PINS, color)` 是怎样把“引脚”和“电平”配对的。

## 5. 第 3 关：效果二“全亮 1 秒、全灭 1 秒”

**目标**：满足任务书的通用写法约束——对三个引脚统一操作，不许抄三遍赋值。

### 填空骨架

在第 2 关的基础上加入 `BLINK_TIMES` 和下面这段：

```python
BLINK_TIMES = ____

while True:
    for color in SINGLE:
        show(color)

    for _ in range(BLINK_TIMES):
        set_all(____)
        time.sleep(____)
        set_all(____)
        time.sleep(____)
```

### 关键区别

正确顺序是：

```text
先把三个脚都设亮 → 只 sleep 一次 → 三个脚都设灭 → 只 sleep 一次
```

错误写法是：

```text
亮红 → sleep → 亮绿 → sleep → 亮蓝 → sleep   # 这是跑马灯，不是白光
```

### 验收

- [ ] 白光 1 秒、全灭 1 秒交替；
- [ ] 闪烁次数由 `BLINK_TIMES` 控制；
- [ ] 全亮/全灭只通过 `set_all` 实现；
- [ ] 没有出现 `leds[0].value(...)`、`leds[1].value(...)`、`leds[2].value(...)` 三行重复。

## 6. 第 4 关：效果三“黄、青、紫”与主循环

**目标**：用两两组合混色，并把三种效果串成无限循环。

### 颜色表

黄 = 红 + 绿 = `(1, 1, 0)`  
青 = 绿 + 蓝 = `(0, 1, 1)`  
紫 = 蓝 + 红 = `(1, 0, 1)`

填空：

```python
PAIRS = ((____, ____, ____), (____, ____, ____), (____, ____, ____))
```

### 主循环

把三段效果按顺序放进 `while True`。填空：

```python
while True:
    for color in SINGLE:
        show(____)

    for _ in range(BLINK_TIMES):
        set_all(____)
        time.sleep(____)
        set_all(____)
        time.sleep(____)

    for color in ____:
        show(____)
```

### 缩进检查

任务要求最大缩进两层，即行首最多 8 个空格。下面这种结构是允许的：

```python
while True:              # 0 个空格
    for color in SINGLE: # 4 个空格
        show(color)      # 8 个空格
```

如果再套一层 `if`，就是 12 个空格，超限。用颜色表代替大量 `if`，就能避免这个问题。

### 验收

- [ ] 黄 → 青 → 紫，各 1 秒；
- [ ] 三种效果整体循环，顺序正确；
- [ ] 切换时无乱闪、无鬼影；
- [ ] 全程序最大缩进不超过两层；
- [ ] 能解释为什么主循环只保留三段顺序逻辑。

## 8. 代码约束自查

```bash
grep -nE '^ {12,}' main.py
```

没有输出 = 没有三层以上缩进。

### 8.2 全亮/全灭没有抄三遍

```bash
grep -n 'value(' main.py
```

直接写 `pin.value(...)` 的地方应该只在 `set_all` 和 `show` 两个函数里。

```bash

```

所有 `sleep` 都应该引用 `DELAY`（或明确的常量），不要散落 `sleep(1)`、`sleep(0.5)`。

```bash
python -m py_compile main.py
```

没有报错 = 语法通过。注意：这只是 PC 上的语法检查，`machine` 模块的真正运行要在 Wokwi 里。

## 9. 常见故障排查

| 现象 | 先查什么 | 常见原因 |
|---|---|---|
| 三色全不亮 | `common` 属性、COM 接线 | 还是默认共阳；COM 接到 3V3；仿真没运行 |
| 某一个颜色不亮 | 该路电阻、该路导线、代码引脚号 | 电阻没接；线没点上；GPIO 编号写错 |
| 颜色不对 | 代码里的 `PINS` 顺序 | R/G/B 线插错；只改一处，不要同时改线和代码 |
| 全亮变成跑马灯 | 全亮代码 | 逐脚点亮且每脚都 sleep；应先把三脚设亮，再 sleep 一次 |
| 切换有鬼影/混色 | `show()` 末尾 | 忘记 `set_all(0)` |
| 程序不循环 | 主循环 | 没有 `while True`，或 `show` 里有阻塞 |
| 在线工程丢失 | 账号、保存 | 未登录；未点保存 |

### 排错总顺序

```text
电源 → 公共端/COM → 电阻 → 代码引脚号 → 颜色线是否插错 → 程序逻辑
```

每修好一个问题，可以在自己的笔记里记一行“现象 → 原因 → 改法”。
